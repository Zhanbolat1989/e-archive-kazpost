# e-archive — Электронный архив (MVP)

Инновационный электронный архив для РК на полностью open-source стеке:
**AI-поиск** (семантический), **OCR** при приёме (рус/каз/eng), **ЭЦП РК** через
NCALayer, антивирус **ClamAV** и **WORM-хранение** оригиналов (MinIO Object Lock).

## Архитектура

```
                        ┌──────────── React PWA (nginx :3000) ───────────┐
                        │  Логин · Каталог · AI-поиск · Приём · ЭЦП       │
                        └───────────────────────┬────────────────────────┘
                                                 │ /api  (reverse proxy)
                        ┌───────────────────────▼────────────────────────┐
                        │              FastAPI backend (:8000)            │
   Приём документа ▶    │  scan ─▶ WORM store ─▶ OCR ─▶ embeddings/index  │
                        └──┬──────────┬───────────┬───────────┬──────────┘
                           │          │           │           │
                    PostgreSQL     MinIO      OpenSearch     ClamAV
                    (метаданные)  (WORM S3)  (гибрид-поиск) (антивирус)

   ЭЦП: браузер ─▶ NCALayer (wss://127.0.0.1:13579) ─▶ CMS ─▶ backend verify
```

| Слой | Компонент |
|------|-----------|
| Backend | FastAPI (Python 3.11) |
| Хранилище | MinIO (S3, Object Lock / WORM) |
| СУБД | PostgreSQL 16 |
| Поиск | OpenSearch 2.13 (BM25 + kNN vector) |
| Эмбеддинги | fastembed / `paraphrase-multilingual-MiniLM-L12-v2` (384d, ONNX, без torch) |
| RAG-чат (LLM) | Ollama / `qwen2.5:3b` (локально, данные не покидают периметр) |
| OCR | Tesseract (rus + kaz + eng) + poppler; опционально [baidu/Unlimited-OCR](https://github.com/baidu/Unlimited-OCR) (VLM, нужен GPU) |
| Антивирус | ClamAV |
| ЭЦП | NCALayer (клиент НУЦ РК), проверка CMS на сервере |
| Frontend | React 18 PWA (Vite) |
| Оркестрация | Docker Compose |

## Быстрый старт

```bash
cp .env.example .env          # при необходимости поменяйте пароли/секреты
docker compose up -d --build
```

Первый запуск дольше обычного: ClamAV скачивает базы сигнатур (~2–3 мин),
backend при первом OCR/индексации подтягивает ONNX-модель эмбеддингов.

| Сервис | URL |
|--------|-----|
| Веб-приложение | http://localhost:3000 |
| API (Swagger) | http://localhost:8000/docs |
| MinIO Console | http://localhost:9001 |
| OpenSearch | http://localhost:9200 |

**Вход по умолчанию:** `admin@earchive.kz` / `admin12345` (задаётся в `.env`).

### Распознавание документов

По умолчанию используется **Tesseract** (rus + kaz + eng) — работает на любой
машине без GPU. Цифровые PDF с текстовым слоем читаются напрямую, минуя OCR.

Опционально можно подключить VLM [baidu/Unlimited-OCR](https://github.com/baidu/Unlimited-OCR):
в отличие от Tesseract он понимает структуру страницы (таблицы, колонки, печати,
рукописный текст) и распознаёт рус/каз/eng без указания языка. Требует NVIDIA
GPU (модель в bf16 не поместится рядом с `qwen2.5:7b` на карте с 8 ГБ VRAM —
нужна карта помощнее или отдельная машина):

```bash
# в .env: OCR_ENGINE=unlimited
docker compose --profile ocr up -d ocr     # первый запуск качает веса модели
```

Сервис вынесен в профиль, потому что делит видеопамять с `ollama`: на одной
карте распределите VRAM через `OCR_GPU_FRACTION` в `.env`. Если сервис не
поднят, backend автоматически откатывается на Tesseract
(`OCR_FALLBACK_TESSERACT=true`), приём документов не прерывается.

## Соответствие ТС-176 (АО «Казпочта»)

Система доработана под техническую спецификацию на ИС «Электронный архив».

| Требование ТС | Реализация |
|---|---|
| Модуль «Управление документами» (п. 4.3) | документы, дела, описи, номенклатура, запросы на выдачу, инвентаризация, уничтожение |
| Модуль «Управление отчетами» (п. 4.4) | 4 сводных отчёта (дела, документы, запросы, акты) + выгрузка CSV |
| Модуль «Помощь» (п. 4.6) | раздел «Помощь» со справкой по всем модулям |
| Модуль «Личный кабинет» (п. 4.7) | профиль, смена пароля, свои сессии, свои согласования |
| Модуль «Предприятие» (п. 4.8) | организация, оргструктура (дерево), подписанты |
| Модуль «Администрирование» (п. 4.9) | роли, учётные записи, текущие сессии с возможностью завершения |
| Маршруты согласования (п. 4.10) | последовательное согласование карточек дел и документов |
| Одновременная работа с документом (п. 6.4) | оптимистичная блокировка версии карточки (409 при конфликте) |
| История использования (п. 6.3) | лист использования документа, включая просмотры |
| Двухфакторная аутентификация (п. 3 разд. 14) | код на email при входе с нового устройства либо при второй сессии |
| Блокировка после 3 попыток (п. 4.4 разд. 14) | автоблокировка учётной записи, разблокировка администратором |
| Аудиторский след (разд. 14) | логин, дата/время, IP, рабочая станция, объект, тип действия, результат |
| Неизменность журнала (п. 3 разд. 14) | удаления нет — только перенос в архив; 90 дн. оперативно, 365 дн. архив |
| SIEM (п. 2.6, 5.2 разд. 14) | поток событий JSON в лог + выгрузка NDJSON для внешней SIEM |
| Выгрузка XML (п. 14.1.4–14.1.5) | архив/дело в XML с ЭЦП, цепочками версий, маршрутами и номенклатурой |
| Антивирус загружаемых файлов (п. 2.10 разд. 14) | ClamAV на приёме |
| ЭЦП НУЦ РК (п. 7 разд. 14) | NCALayer, проверка CMS на сервере |

**Вне рамок ПО** (услуги и инфраструктура): научно-техническая обработка и
физическое сканирование (разд. 8–11), SLA и время реакции (разд. 13),
SSL-сертификат и интеграция с корпоративной SIEM — это договорные и
инфраструктурные обязательства исполнителя, а не функции приложения.

### Второй фактор входа

Включён по умолчанию (`TWOFA_ENABLED=true`). Пока `SMTP_HOST` не задан, код
подтверждения не отправляется письмом, а пишется в журнал сервера:

```bash
docker compose logs backend | findstr "код для входа"
```

Для промышленной эксплуатации заполните параметры `SMTP_*` в `.env`.

## Что демонстрирует MVP

1. **Приём** — загрузка PDF/скана → ClamAV → WORM-хранение → OCR → индексация.
   Статус документа обновляется в интерфейсе в реальном времени.
2. **AI-поиск** — три режима: гибридный (смысл + слова), семантический (по смыслу),
   ключевой. Ищет по распознанному тексту, а не только по названию.
2а. **ИИ-агент (диалог)** — диалоговое окно с памятью: задаёте вопросы по
   СОДЕРЖИМОМУ документов, включая уточняющие («а на какой срок он заключён?»).
   Агент ищет по архиву, читает документы и формирует ответ со ссылками на
   источники; показывает свои действия. Всё локально (Ollama), данные не
   покидают периметр. Первый запуск скачивает модель (~2 ГБ).

   Режимы (`.env` → `AGENT_TOOL_LOOP`): по умолчанию `false` — надёжный
   retrieval-ответ (подходит для `qwen2.5:3b` на CPU). Для автономного
   tool-calling агента переключите на `true` и используйте модель 7b+
   (`OLLAMA_MODEL=qwen2.5:7b`) — качественнее, но медленнее на CPU.
3. **ЭЦП РК** — в карточке документа кнопка «Подписать и проверить ЭЦП» вызывает
   NCALayer, получает CMS и проверяет его на сервере (извлечение ИИН/ФИО подписанта).
4. **Роли** — admin / archivist / viewer (JWT).

## Роли и разграничение

- **admin** — всё, включая создание пользователей и удаление записей.
- **archivist** — приём, описание, проверка ЭЦП.
- **viewer** — только просмотр и поиск.

## Разработка без Docker

Backend:
```bash
cd backend && pip install -r requirements.txt
uvicorn app.main:app --reload      # нужны запущенные postgres/minio/opensearch/clamav
```
Frontend:
```bash
cd frontend && npm install && npm run dev      # http://localhost:3000, проксирует /api
```

## Ограничения MVP (дорожная карта)

- **ЭЦП ГОСТ**: НУЦ РК выпускает и ГОСТ 34.10 сертификаты. Python `cryptography`
  их не проверяет — такие подписи помечаются `unsupported` (личность подписанта
  всё равно извлекается). RSA-сертификаты проверяются полностью.
  Далее: интеграция GOST-провайдера / полная валидация цепочки до корня НУЦ РК.
- **Keycloak** — на MVP используется встроенный JWT; замена на Keycloak/OIDC — следующий шаг.
- **Alfresco** — сознательно заменён лёгким FastAPI-ядром для скорости MVP.

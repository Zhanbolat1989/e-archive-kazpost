# Инструкция администратора: ИС «Электронный архив» АО «Казпочта»

Редакция `EDITION=kazpost`, техническая спецификация ТС-176 от 03.04.2026.
План внедрения и соответствие требованиям — [plan-kazpost.md](plan-kazpost.md),
общее описание системы — [README](../README.md).

Ниже `dc` означает команду Docker Compose промышленного контура:

```bash
docker compose -f docker-compose.yml -f docker-compose.kazpost.yml
```

Для тестовой среды — свой файл настроек и третий файл Compose:

```bash
docker compose --env-file .env.kazpost-test -f docker-compose.yml -f docker-compose.kazpost.yml -f docker-compose.kazpost-test.yml
```

У тестовой среды свой адрес (порт 8443), поэтому в `.env.kazpost-test` свои
`WEBAUTHN_RP_ID` и `WEBAUTHN_ORIGINS` (например, `https://ДОМЕН:8443`).

## 1. Состав контура

| Сервис | Назначение | Наружу |
|---|---|---|
| `frontend` | веб-интерфейс и мобильная версия (PWA), nginx с TLS | 80 → 443 |
| `backend` | API, аудиторский след, фоновые проверки доступности для SLA | нет |
| `postgres` | база данных; журнал защищён триггерами от удаления и правки | нет |
| `minio` | хранилище оригиналов с WORM-блокировкой | нет |
| `opensearch` | полнотекстовый и векторный поиск | нет |
| `ollama`, `ocr` | языковая модель и распознавание (по ресурсам контура) | нет |
| `clamav` | антивирусная проверка загружаемых файлов | нет |
| `ncanode` | проверка ЭЦП по Правилам № 1187 (ГОСТ 34.10-2015, OCSP) | нет |
| `backup-db`, `backup-objects` | резервные копии базы и хранилища | нет |

Тестовая среда (`docker-compose.kazpost-test.yml`) — отдельный проект со своими
томами и конфигурацией `.env.kazpost-test`, порты 8080/8443. Обновление сначала
ставится туда (требование ИБ ТС-176 об испытании обновлений).

## 2. Первое развёртывание

1. `cp .env.kazpost.example .env` и заполнить все значения с пометкой
   **ЗАМЕНИТЬ**: `SECRET_KEY`, пароли PostgreSQL и MinIO, SMTP, первый
   администратор, `WEBAUTHN_RP_ID` и `WEBAUTHN_ORIGINS`. В промышленном режиме с
   демонстрационными или пустыми значениями сервис не запустится и перечислит
   причины в журнале.
2. Положить сертификат доверенного УЦ в `./certs`: `fullchain.pem`, `privkey.pem`.
3. Закрепить версию образа NCANode 3.x в `docker-compose.kazpost.yml` вместо `latest`.
4. `dc up -d --build`.
5. Проверить готовность: `curl -k https://ДОМЕН/api/health/ready` отвечает `200`
   (`503` — недоступны база, поиск или хранилище; подробности в `dc logs backend`).
6. Войти первым администратором и сменить пароль в Личном кабинете.

Схема базы дотягивается при каждом старте автоматически: новые таблицы и
колонки добавляются, существующие данные не трогаются.

## 3. Первичная настройка — по порядку

| Шаг | Где | Что сделать |
|---|---|---|
| 1 | Предприятие | сведения об организации (подставляются в печатные формы) |
| 2 | Безопасность | учётные записи, роли, право подписи |
| 3 | Предприятие | оргструктура: подразделения и **руководитель — учётная запись**; без неё шаг «руководитель подразделения» в маршруте не назначится |
| 4 | Предприятие | шаблоны маршрутов согласования: шаги задаются позициями оргструктуры |
| 5 | Администрирование → Справочники | виды архивных запросов, фонды, цели выдачи дел |
| 6 | Администрирование → Доступ к документам | категории документов, доступные ролям |
| 7 | Номенклатура | статьи с видами документов; отправка на согласование по шаблону; ввод в действие только после согласования |
| 8 | НТО и передача | протоколы ЭК/ЦЭК/ЭПК по мере заседаний |

### Роли

| Роль | Может |
|---|---|
| Администратор | всё, включая учётные записи, роли, настройки и утверждение актов |
| Архивариус | приём и сканирование, дела, описи, копии, НТО, передача, запуск маршрутов |
| Читатель | просмотр и поиск в пределах разрешённых категорий |
| Аудитор ИБ | журнал аудита, учётные записи и сессии, отчёт по ПДн; **без доступа к содержимому документов** (разд. 14 п. 5.1) |

## 4. Вход и учётные записи

- **Блокировка.** Три неверных пароля подряд блокируют запись; разблокирует
  администратор в разделе «Безопасность». Отключённая запись теряет все сессии.
- **Второй фактор.** Код на email при входе с нового браузера или при второй
  активной сессии. Без SMTP код пишется в журнал `backend` — только для стенда.
- **Сессии.** Администратор видит и завершает любые сессии; пользователь — свои.
- **Вход по биометрии (разд. 14 п. 4.2).** Включается `WEBAUTHN_ENABLED=true`.
  Пользователь входит по паролю, в Личном кабинете нажимает «Добавить это
  устройство» и подтверждает отпечатком, лицом или PIN телефона; дальше на
  странице входа — «Войти по биометрии». Работает только по HTTPS на домене из
  `WEBAUTHN_RP_ID`. Потерян телефон — пользователь входит по паролю с другого
  устройства и удаляет ключ в Личном кабинете; если нужно срочно — администратор
  отключает учётную запись: по ключу отключённая запись не входит.

## 5. Регламентные действия

| Периодичность | Действие | Где |
|---|---|---|
| ежедневно | проба здоровья `backup-db` (`dc ps`): `unhealthy` — последней удачной копии больше двух интервалов | консоль |
| ежедневно | новые инциденты ИБ и заявки с истекающим сроком реакции | Заявки и SLA |
| ежемесячно | отчёт SLA за месяц: % доступности, % устранённых в срок, размер оплаты по п. 13.1.3 | Заявки и SLA → отчёт |
| ежеквартально | информация о попытках НСД к персональным данным (разд. 14 п. 8) | Управление отчетами |
| по регламенту ИБ | выгрузка журнала для SIEM (NDJSON), перенос старых записей в архив | Безопасность → Аудиторский след |
| перед обновлением | копия базы, установка на тестовую среду, затем в контур; событие обновления появится в журнале | консоль |

Удалить или исправить запись журнала нельзя ни через интерфейс, ни прямым SQL:
PostgreSQL отклоняет такие операции, разрешён только перенос в архив.

## 6. ЭЦП

`SIGNATURE_VERIFIER=ncanode`: подпись подтверждается, только если NCANode
проверил цепочку до корня НУЦ РК и получил статус отзыва по OCSP. Недоступен
NCANode или не получен статус — подпись отмечается «ЭЦП не подтверждена», и
удостоверить ею электронную копию нельзя. После смены версии NCANode сверьте
формат ответа тестом `tests/test_ncanode.py`.

## 7. Резервное копирование и восстановление

Порядок восстановления — в разделе README «Резервное копирование и
восстановление». Восстановление отрабатывается на тестовой среде не реже раза в
квартал: копия, которую ни разу не разворачивали, копией не считается.

## 8. Проверки на стенде перед приёмкой

Эти свойства автотестами локально не проверяются — их подтверждают на
развёрнутом контуре.

1. **Автотесты в контейнере**, включая `test_ecopies.py`:
   ```bash
   dc exec backend pip install pytest
   dc cp backend/tests backend:/app/tests
   dc cp backend/pytest.ini backend:/app/pytest.ini
   dc exec backend python -m pytest
   ```
2. **Защита журнала в СУБД** — удаление должно завершиться ошибкой «Удаление
   записей аудиторского следа запрещено» (транзакция откатывается в любом случае):
   ```bash
   dc exec postgres psql -U earchive -d earchive -c "BEGIN; DELETE FROM audit_log; ROLLBACK;"
   ```
3. **NCANode** — проверка настоящей подписи ГОСТ и подписи отозванным сертификатом.
4. **Вход по биометрии** — добавление ключа и вход с Android и iPhone по HTTPS.
5. **Печатные формы** — описи, акты, историческая справка, предисловие к описи,
   акт приёма-передачи открываются в PDF; казахские заголовки новых форм сверяет
   архивист заказчика.
6. **Пакет передачи в госархив** — выгрузка акта на несколько больших дел,
   `manifest.json` без записей в `missing`.
7. **Резервная копия** — восстановление на тестовой среде по README.

## 9. Диагностика

| Симптом | Где смотреть |
|---|---|
| сервис не стартует | `dc logs backend` — список небезопасных настроек или ошибка миграции |
| письма с кодами не приходят | `dc logs backend`, настройки `SMTP_*` |
| «ЭЦП не подтверждена» у всех подписей | `dc logs ncanode`, доступ контура к OCSP НУЦ РК |
| кнопка «Войти по биометрии» не появляется | `WEBAUTHN_ENABLED`, открытие по HTTPS, поддержка браузером |
| ключ доступа не принимается | совпадение домена с `WEBAUTHN_RP_ID` и адреса с `WEBAUTHN_ORIGINS` |
| маршрут согласования не отправляется | у подразделения объекта или отправителя нет руководителя-учётной записи |
